I Built a $0 Per Month AI Survey System With QR Codes and Sentiment Analysis

Someone scans a QR code at an event. Within seconds, an AI reads their feedback and classifies their sentiment. The whole pipeline costs nothing to run.

9 min read

I needed a way to collect feedback at events. Real, honest feedback. Not "dump responses into a spreadsheet and maybe look at it next week." I wanted the whole pipeline: someone scans a QR code, fills out a quick survey, and within seconds an AI reads their response, classifies the sentiment, and the results get packaged into a report.

All automated. All free.

So I built exactly that. The system uses n8n (an open-source workflow automation platform I self-host with Docker) as the brain, Google Forms and Sheets as the data layer, Groq's API running Llama 3.1 for sentiment classification, QuickChart for QR code generation, and a Telegram bot as the trigger and notification channel. There is even a 5-hour kill switch that automatically shuts down the survey after the event ends, exports everything to PDF, and emails the results.

Why I Built This

The entire system costs zero dollars per month to operate. Groq offers a generous free tier for LLM inference. Google Forms and Sheets are free. n8n is self-hosted. Telegram bots are free. QuickChart is free.

This is what I mean by cost-conscious engineering. You do not need a big budget to build sophisticated systems. You need good architecture.

Key insight: Every architectural decision in this project was filtered through "can I do this for free?" Not because I am cheap, but because cost discipline forces elegant design. Free tiers are generous if you architect around them. The constraint of zero budget produced a cleaner system than unlimited budget would have.

Core Concepts

Workflow Orchestration with n8n. Think of n8n like a series of dominoes. When the first one falls (a trigger event), each subsequent domino falls in order, and each one does something useful along the way. Except these dominoes can call APIs, read databases, run code, send messages, and make decisions. n8n gives you a visual canvas where you drag nodes around and connect them with wires. Each node is a step: "fetch data from this API," "transform this JSON," "send this Telegram message." It is like Zapier or Make, but open-source and self-hosted, which means I control everything and pay nothing.

LLM-Powered Sentiment Classification. When a survey response comes in, I do not just store it. I send it to Groq's API, which runs Llama 3.1. I give the LLM a prompt like: "Classify this feedback as either 'empathetic/positive' or 'needs growth/constructive'." The model reads the response and returns a label.

Key insight: LLMs are not just for chatbots. They are classification engines, summarizers, and pattern detectors. Using them for structured classification tasks is one of the most practical applications in production systems today. Send text in, get labels out.

Event-Driven Architecture. Nothing in this system runs on a schedule polling for changes. Things happen in response to events: "A Telegram message arrived" triggers QR generation. "A new form response appeared in the Google Sheet" triggers sentiment analysis. "Five hours have passed" triggers the kill switch. This is the same pattern behind AWS Lambda, Google Cloud Functions, and every modern microservice. Events in, actions out.

The Kill Switch Pattern. After 5 hours, the system automatically stops accepting responses, generates a PDF summary, and emails it to the organizer. This prevents stale surveys from collecting junk data after an event ends. In production systems, this is similar to TTLs on cache entries or auto-expiring tokens. The principle: every resource should have a defined lifecycle.

Docker and Self-Hosting. n8n runs inside a Docker container defined in docker-compose.yml. Think of Docker as a shipping container for software. It packages the application with all its dependencies so it runs the same way everywhere. My laptop, a cloud VM, a Raspberry Pi. docker-compose up and the whole system is live.

An event organizer sends a command to the Telegram bot. n8n catches the message, calls QuickChart to generate a QR code pointing to a Google Form, and sends the QR image back via Telegram. The organizer displays or prints the QR code at the event.

Attendees scan the code with their phones and fill out the survey. Responses land in a Google Sheet automatically. When a new row appears, n8n picks it up, sends the free-text feedback to Groq's Llama 3.1, and writes the sentiment label back to the Sheet.

After 5 hours, a timer fires. The workflow closes the form, exports the Sheet to PDF, and emails the report. Throughout the process, the Telegram bot sends status updates: "Survey started," "15 responses collected," "Survey closed, report sent."

What I Learned

  1. Workflow orchestration is a superpower. Tools like n8n, Airflow, and Prefect let you automate complex multi-step processes. This is the backbone of data engineering and DevOps.
  2. LLMs as classification tools. Forget chatbots. The real value of LLMs in production is structured tasks: classification, extraction, summarization. I send text in, I get labels out.
  3. Event-driven thinking changes everything. When you stop thinking in terms of "run this script every hour" and start thinking "react when this happens," your systems become more responsive and more efficient.
  4. Docker makes reproducibility trivial. One docker-compose.yml and anyone can run my entire system. This is the foundation of modern deployment.
  5. API integration is a career-long skill. This project chains together five different APIs: Telegram, QuickChart, Google Sheets, Groq, and email. Learning to read API docs, handle auth, and parse responses never stops being useful.
  6. Cost engineering is a design discipline. Building production-quality systems on free tiers teaches you to evaluate trade-offs. What does the free tier give you? What are the rate limits? What breaks if you scale?
  7. Shell scripting is underrated. The setup and test scripts in the scripts/ directory automate the boring parts. Knowing bash well enough to automate setup and testing is a quiet superpower.

Why This Matters for Your Career

Building automated, event-driven systems is one of the most in-demand skills in modern engineering. Here are some interview questions this project prepares you to answer.

Q: How would you build an automated data collection pipeline?

Walk through the full flow: trigger mechanism (Telegram bot), data capture (Google Forms), storage (Google Sheets), processing (Groq LLM for sentiment), and reporting (PDF export plus email). Emphasize the event-driven nature. Nothing polls. Everything reacts.

Q: What is workflow orchestration, and how is it different from a cron job?

A cron job says "run this at midnight." Orchestration says "run step B after step A succeeds, run step C in parallel, and if step B fails, retry three times then alert me." n8n, Airflow, and Prefect are orchestrators. Cron is just a scheduler. Orchestration gives you dependency management, error handling, retries, and monitoring.

Q: How do you use LLMs in production beyond chatbots?

Classification, entity extraction, summarization, translation, and data enrichment. In this project, I use Llama 3.1 for binary sentiment classification. The key is structured prompting: give the model clear instructions and a constrained output format. This is the same pattern behind every AI feature in modern SaaS products.

Q: How do you design systems that cost nothing to operate?

Map your requirements to free tiers. Google Sheets for storage. Groq for LLM inference. Self-hosted n8n. Telegram bots. The design principle is to minimize external paid services by leveraging free-tier offerings and self-hosting where possible. The trade-off is operational overhead, since you maintain the infrastructure yourself.

Q: What would you change if this needed to scale to 10,000 respondents?

Replace Google Sheets with PostgreSQL. Replace self-hosted n8n with a managed orchestrator or AWS Step Functions. Add a queue (SQS or RabbitMQ) between form submission and sentiment analysis to handle bursts. The architecture is already event-driven, so scaling is mostly about swapping components, not redesigning.
