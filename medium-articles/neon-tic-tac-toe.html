I Over-Engineered Tic-Tac-Toe With Three.js and Generative Audio. Here is Why.

A 3D parallax board, chromatic aberration trails, generative drone soundscapes, and confetti. All for a game you used to play on napkins.

8 min read

I took the simplest game in the world and turned it into a full sensory experience. A 3D parallax board that tilts as you move your mouse. An animated liquid background. Chromatic aberration cursor trails. A generative space drone soundscape. Confetti when you win.

Yes, it is absurd. That was the point.

When you build something "serious," you play it safe. When you build something absurd, you experiment. I touched Three.js, the Web Audio API, the Canvas API, CSS3 animations, touch event handling, Express.js, and Google Cloud Run deployment in a single project. Every one of those is a real skill that shows up in real jobs. The game was the excuse. The learning was the point.

Why I Built This

I wanted to understand how the modern browser works as a platform. Not as a document viewer. As an engine for graphics, sound, and interactivity.

The best way to learn a dozen browser APIs is to give yourself permission to go completely overboard. Constraints breed creativity, and absurd scope breeds breadth. By adding 3D rendering, generative audio, canvas effects, and cloud deployment to a tic-tac-toe game, I covered more ground in one project than most tutorial series cover in a semester.

Key insight: The modern browser can do 3D graphics, generate audio in real time, process images, and run at 60 frames per second. You do not always need a native app. Learning what the browser can do changes how you think about every project.

Core Concepts

Three.js and 3D Rendering. Think of your browser as a window into a 3D world. Three.js gives you the toolkit to build that world. You create a scene (the room), a camera (your eyes), and a renderer (the artist who paints what the camera sees onto your screen). For this project, I use Three.js for the parallax board tilting. As you move your mouse, the board subtly rotates in 3D space, like holding a card and tilting it under a light. Under the hood, that is matrix math and WebGL shaders. Three.js wraps it all in a friendly API so you can say "rotate this 5 degrees on the Y axis" instead of writing raw GPU instructions.

Web Audio API and Generative Sound. The Web Audio API is like having a tiny recording studio inside the browser. You create oscillators (think: tuning forks vibrating at specific frequencies), connect them through effects like reverb and filters, and route them to the speakers. My space drone soundscape is not a pre-recorded MP3. It is generated in real time by layering low-frequency oscillators with slow modulation. Imagine three people each humming a slightly different note and slowly changing pitch. That is generative audio.

Key insight: Audio in the browser is a graph of connected nodes, just like a signal chain in a recording studio. Source nodes flow into processing nodes, which flow into the destination. Understanding this graph model is how all audio software works, from GarageBand to professional DAWs.

Canvas API for Visual Effects. The HTML Canvas is your digital drawing surface. Every frame (roughly 60 times per second), I clear the canvas and redraw everything. The chromatic aberration cursor trails work by drawing the same shape three times, slightly offset, in red, green, and blue, mimicking how a cheap camera lens splits light. The liquid background uses simplex noise to animate flowing color blobs, creating that lava-lamp effect.

Game State Management. Even Tic-Tac-Toe needs state management. I track whose turn it is, what is in each cell, and whether someone has won. This is the same fundamental pattern behind every interactive app: you have state (the data), actions (user clicks a cell), and rendering (update the UI to reflect the new state). React, Vue, Redux; they all formalize this exact loop. Tic-Tac-Toe is the perfect sandbox to internalize it before frameworks add complexity.

The server starts with Express, serving everything in the public/ directory. When the browser loads the page, Three.js initializes a 3D scene with the tic-tac-toe board positioned in 3D space. Mouse move events feed into board rotation, creating the parallax tilt.

A canvas layer sits behind the game board, running the liquid background animation and cursor trail effects at 60fps via requestAnimationFrame. On the first user interaction (browsers require a gesture before playing audio), the generative soundscape starts.

The game loop is straightforward: player clicks a cell, state updates, UI re-renders, a win-check function scans rows, columns, and diagonals. If someone wins, confetti explodes and a victory sound triggers. For mobile, touch events map to the same handlers as mouse events.

What I Learned

  1. Browser APIs are powerful. The modern browser can handle 3D graphics, generate audio, and process images at 60fps. You do not always need a native app.
  2. requestAnimationFrame is your animation heartbeat. Every smooth animation in the browser uses this function. It syncs with the browser's repaint cycle, pauses when tabs are hidden, and gives you a high-resolution timestamp.
  3. WebGL and Three.js fundamentals transfer. Scenes, cameras, renderers, meshes, materials, lights. This vocabulary carries directly to game development and AR/VR work.
  4. The Audio Context graph model is universal. Understanding signal routing (source to effect to destination) is how all audio software works.
  5. Canvas 2D rendering skills are versatile. Drawing shapes, clearing frames, compositing layers. The same skills power data visualizations, image editors, and browser games.
  6. Express.js patterns are bread and butter. Middleware, static file serving, route handling. These are the fundamentals of Node.js backend work.
  7. Cloud Run deployment is approachable. Containerizing and deploying a web app is a skill every developer needs, and Cloud Run removes most of the operational complexity.

Why This Matters for Your Career

Creative coding projects demonstrate technical range that CRUD apps simply cannot. Here are some interview questions this project prepares you for.

Q: What is the difference between Canvas 2D and WebGL?

Canvas 2D gives you a simple drawing API for rectangles, arcs, text, and images. WebGL gives you access to the GPU for hardware-accelerated 3D rendering. Three.js wraps WebGL so you do not have to write raw shader code. Use Canvas 2D for 2D effects. Use WebGL and Three.js when you need 3D or heavy parallel computation.

Q: How does requestAnimationFrame differ from setInterval for animations?

setInterval fires at a fixed interval regardless of whether the browser is ready to repaint. requestAnimationFrame syncs with the browser's repaint cycle (usually 60fps), pauses when the tab is hidden, and gives you a high-resolution timestamp for smooth timing. Always use requestAnimationFrame for visual animations.

Q: Explain the Web Audio API's node graph architecture.

The Web Audio API models audio as a directed graph. You create an AudioContext, then build a chain of nodes: sources (oscillators, audio buffers) connect to processing nodes (gain, biquad filter, delay) which connect to the destination (speakers). Data flows through the graph in real time. This is exactly how hardware synthesizers and mixing boards work.

Q: Why would you over-engineer a simple game?

To learn. Absurd scope breeds breadth. By adding 3D, generative audio, canvas effects, and cloud deployment to a tic-tac-toe game, I touched more browser APIs in one project than most tutorials cover in a semester. The game is the excuse; the learning is the point.
