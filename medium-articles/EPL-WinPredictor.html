I Built a Model That Predicts Premier League Matches. Here is What Feature Engineering Really Looks Like.

XGBoost, Elo ratings, SHAP explainability, and the 80% of machine learning that nobody talks about enough.

12 min read

Predicting football match outcomes sounds like a party trick. But it is really just asking one question: given everything that has happened so far this season, what is most likely to happen next Saturday?

I built a machine learning model to answer that question for the English Premier League. It uses XGBoost, Random Forest, Logistic Regression, and a feature engineering pipeline that took raw match data and turned it into something a model could actually learn from. This was my BrainStation capstone project, and I threw everything I had at it.

Here is why this matters beyond football. Every company with historical data wants to predict future outcomes. Will this customer churn? Will this stock go up? Will this patient be readmitted? The techniques I used here are the exact same patterns you would use in any predictive modeling job. Football just made it fun to learn.

Why I Built This

Raw match data is boring. Team A scored 2, Team B scored 1. That tells you what happened, not why, and certainly not what will happen next.

The real magic lives in feature engineering. When you compute rolling 5-game averages, dynamic Elo ratings, expected goals differentials, and head-to-head records, suddenly your model has rich context. That transformation from raw data to meaningful features is the single most valuable skill in applied ML.

I wanted to prove that to myself. And I wanted a capstone project that would show interviewers I understood the full pipeline, not just the model.fit() call.

Core Concepts, Explained Simply

Feature Engineering with Rolling Averages. Imagine you are trying to predict how well a student will do on their next exam. Looking at just their last test score is not great. But if you average their last 5 tests, you get a much better picture of their current form. That is what rolling averages do for football teams. Instead of "they won last week," the model sees "they have averaged 1.8 goals and 58% possession over their last 5 matches."

Key Insight: Feature engineering contributed more to model performance than algorithm selection. The same XGBoost model with raw features performed significantly worse than with engineered features. This is true in most real-world ML projects.

Elo Ratings. Chess players have Elo ratings that go up when they beat strong opponents and down when they lose to weak ones. I implemented the same system for Premier League teams. After every match, each team's rating updates based on the result and the strength of their opponent. So beating Man City is worth more than beating a relegation team. This gives the model a dynamic measure of true team quality that adapts throughout the season.

XGBoost (Extreme Gradient Boosting). Think of it like this: you have a team of students taking a test. The first student takes the test and gets some questions wrong. The second student focuses specifically on the questions the first student missed. The third student focuses on what the first two still got wrong. By the time you combine all their answers, the team collectively aces it. That is XGBoost. Each "tree" learns from the mistakes of previous trees.

Random Forest. Instead of students learning from each other's mistakes, imagine you give 100 different students slightly different versions of the test. Each works independently. Then you take a majority vote. The wisdom of the crowd tends to be more accurate than any single student.

SHAP (SHapley Additive exPlanations). After your model makes a prediction, your boss asks "but WHY does it think Liverpool will win?" SHAP answers this by computing how much each feature contributed to that specific prediction. It is borrowed from game theory. If the prediction is a team project, SHAP figures out exactly how much each team member contributed to the final grade.

How It Works

The pipeline has five stages, and the middle one is where 80% of the value lives.

  Raw Match Data        Feature Engineering         Model Training         Prediction
  +-------------+       +-------------------+       +-----------------+    +------------+
  | Scores      |       | Rolling Averages  |       | XGBoost         |    | Win / Draw |
  | Shots       | ----> | Elo Ratings       | ----> | Random Forest   | -> | / Loss     |
  | Possession  |       | xG Differentials  |       | Log. Regression |    | Probs      |
  | xG          |       | Streaks           |       | + SHAP          |    |            |
  +-------------+       | Head-to-Head      |       +-----------------+    +------------+
                        +-------------------+

Step 1: Data Loading. I load CSV files of Premier League match data containing dates, teams, scores, shots, possession, expected goals, and more.

Step 2: Preprocessing. Clean column names, handle missing values, convert dates to numeric format, and encode team names. One subtle detail: I transform kick-off times into cyclical features using sine and cosine, so the model understands that 23:00 and 01:00 are close together.

Step 3: Feature Engineering. This is the heart of the project. I compute rolling 5-game averages for goals, shots, possession, and xG. I calculate win/loss streaks to capture momentum. I generate interaction features like xG differential (attacking power minus opponent's) and shot accuracy ratios. I build head-to-head statistics between specific team pairs. And I implement dynamic Elo ratings that update after each match.

Step 4: Model Training. Train XGBoost, Random Forest, and Logistic Regression. Evaluate each with precision, recall, and F1-score. Use SHAP to understand which features drive predictions.

Step 5: Prediction. Prepare upcoming match data with the same features, run through the best model, and output win/draw/loss probabilities.

What I Learned

  1. Feature engineering is the real ML superpower. Raw data is almost never enough. You need to transform it into meaningful signals. This one lesson transfers to every ML project you will ever work on.
  2. Know when to use boosting vs. bagging. XGBoost (boosting) reduces bias by learning sequentially. Random Forest (bagging) reduces variance through parallel independent trees. Understanding this distinction is fundamental.
  3. Accuracy is a misleading metric for imbalanced classes. Draws happen less often than wins or losses. Precision, recall, and F1 give you a much more honest picture of model performance.
  4. Explainability is not optional. SHAP turns a black-box model into something you can defend in a meeting. This is increasingly required in industry, especially in regulated domains.
  5. Time-series data requires special handling. You cannot randomly split time-series data without leaking future information. Chronological train/test splits and rolling window features are essential.
  6. Domain knowledge directly improves features. Knowing that home advantage matters, that form fluctuates, and that xG is more reliable than raw goals produced better features than any automated feature selection method.
  7. Dask scales pandas when data outgrows memory. When the dataset got too large for pandas, Dask let me process it in chunks with a familiar API. Think of it as hiring a moving crew instead of carrying everything yourself.

Why This Matters for Your Career

If you are preparing for machine learning or data science interviews, this project covers a remarkable range of commonly asked questions. Here are a few, and how building this project prepares you to answer them.

"Walk me through a feature engineering project." Talk about how you took raw match data and engineered rolling averages, Elo ratings, interaction features, and streaks. Emphasize that feature engineering contributed more to model performance than algorithm selection.

"What is the difference between boosting and bagging?" Boosting (XGBoost) is sequential; each tree learns from predecessors' errors and reduces bias. Bagging (Random Forest) is parallel; trees train on random data subsets, and majority vote reduces variance. You used both and can compare their real-world performance.

"How do you make ML models explainable?" Describe your SHAP implementation. Explain how Shapley values attribute prediction contributions to individual features. This is a huge plus for regulated industries like finance and healthcare.

"How do you handle time-series data in ML?" Explain why random splits cause future leakage. Describe rolling window features, the importance of chronological train/test splits, and how Elo ratings capture temporal dynamics.

"How do you handle a dataset that does not fit in memory?" Explain your use of Dask: lazy evaluation, chunked processing, and a DataFrame API that mirrors pandas. Discuss when to use Dask vs. Spark vs. simply provisioning more RAM.
